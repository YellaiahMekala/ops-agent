# PQ1.2.2: live end-to-end, alert to triage email (2026-11-18)

Status: **run 2026-11-18, local, paid, approved (cap 0.03 USD). Passed for the ops-agent path; the "through the
gateway ledger" part could not apply (section 4).**

## 1. Setup

- ai-gateway demo: `demo/up.sh telemetry` (gateway, Postgres, Redis x2, Prometheus, Alertmanager, Grafana, Jaeger,
  Mailpit). The gateway runs on its stub provider; ops-agent does not use it for the model.
- ops-agent: `./mvnw -B -ntp package -DskipTests && docker build -t ops-agent:local .`, then
  `docker compose -f deploy/compose.yaml up -d` with `OPENAI_API_KEY` and `OPSAGENT_WEBHOOK_TOKEN` in the environment
  only (the key was loaded from the platform `.env` into the shell, a random webhook token was generated; neither is
  printed or stored here). Legacy shared-token mode (default on), tenant `legacy`.
- Model: `gpt-4o-mini` (config default), OpenAI called directly, `maxRetries 0`, `store false`.
- Mail: ops-agent's own Mailpit (http://127.0.0.1:8026). No real SMTP.
- No gateway budget ceiling was set, because no spend goes through the gateway (section 4). The cap was held by the
  ops-agent run guardrails (max 24000 tokens per run) and the task cap.

## 3. Email (Mailpit)

Three mails, one per run, none for the duplicate. Example (run 1), subject
`[TRIAGE] GatewayProviderErrorRatio (page) owner=gateway-oncall`, from the ops-agent address to the owner mailbox at
the `.invalid` domain. Body sections: WHAT FIRED (labels, summary), FINDINGS (gateway healthy, all components UP; no
provider errors or calls in the last two minutes), LIKELY CAUSE (`unknown`, confidence HIGH), RUNBOOK (the section
quoted verbatim), EVIDENCE (dashboard link; the `expression` field was empty), RUN (id, DONE, steps 5, tool calls 4,
tokens 4709/152, "changed nothing").

## 4. Result

Passed:
- Alert to Alertmanager to `/alerts` (legacy token) to a run to the model with the four read-only tools to an email:
  3 of 3 runs `DONE`, 13 `tool_audit` rows all `OK`, no guardrail stop.
- Dedupe: the repeated delivery answered `{"intake":["DUPLICATE"]}` and made no run, no model call and no mail.

Did not apply or failed:
- **Gateway ledger and cost: 0 rows.** `invocation_ledger` in the gateway database had 0 rows after the runs.
  ops-agent calls OpenAI directly by design (ai-gateway ADR-1 and ADR-18: the gateway has no tool calling and the agent
  loop is tool calling), so no model call crossed the gateway. The task text expected gateway ledger rows; this
  architecture cannot produce them. Routing through the gateway would need gateway tool-call passthrough, which is a
  design change, not a configuration.
- Quality: the FINDINGS and a "likely cause unknown, confidence HIGH" pairing are a fair reading of a healthy system,
  but the confidence label next to "unknown" is odd and is a prompt-quality item, not a failure of the path.
- The `EVIDENCE expression:` line was empty in run 1.
- The JWT path was not exercised live (no ops-agent client in the platform realm yet).
